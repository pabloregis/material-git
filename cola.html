Os comandos do treinamento, com a tradução de cada palavra. Na dúvida, comece por git status.

O ciclo de todo dia

Nos times que usam a develop, como no mural, o trabalho parte dela, e a main só recebe a develop nos releases (lançamentos). Em times sem develop, troque develop por main.

git switch develop                # troca para a develop (desenvolvimento)
git pull                          # puxa o que o time enviou
git switch -c minha-tarefa        # cria a branch da tarefa e troca para ela
# ... edita os arquivos ...
git status                        # situação: o que mudou?
git add .                         # adiciona tudo à preparação
git commit -m "Diz o que mudou"   # registra, com mensagem
git push -u origin minha-tarefa   # empurra para o GitHub; depois abra o pull request para a develop

Resolver um conflito

  1. Abra o arquivo que o Git apontou e procure <<<<<<<.
  2. Entre <<<<<<< HEAD e ======= está a sua versão (HEAD = onde você está); entre ======= e >>>>>>>, a que chega.
  3. Deixe o texto final como deve ficar e apague as três linhas de marcação. No editor, use os botões acima do conflito: Accept Current Change (fica a sua), Accept Incoming Change (fica a que chega) ou Accept Both Changes (ficam as duas). Em português: Aceitar Alteração Atual, de Entrada ou Ambas as Alterações.
  4. Rode git add arquivo e git commit -m "Resolve conflito em arquivo".
